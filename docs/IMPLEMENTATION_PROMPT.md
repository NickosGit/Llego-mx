## Data layer (already written: use it, don't redesign it)

## Config: `src/config/corridor.ts`

```ts
export const corridor = {
  route: "Ruta 120",
  origin: "Walmart Las Alamedas (Atizapán)",
  transferPoint: "Metro El Rosario",
  destination: "Cámara de Diputados (San Lázaro)",
  restOfTripMin: 75,        // Metro L6→L5→L1 + walk. Rodolfo's estimate, shown as "estimado de Rodolfo"
  defaults: { arriveBy: "07:00", usualDepart: "04:45" },
  seatGoal: 0.6,            // "most days" = 6 of 10 or more
  searchWindowMin: 60,      // never suggest leaving more than 1 h earlier than usual
};
```

Inputs come from query params (`?llegar=07:00&sales=04:45&dia=martes`) with these defaults. Nothing about the rider is stored server-side.

## Core logic: `src/lib/planSeat.ts` (pure function, unit-tested)

```
input: arriveBy, usualDepart, dayType, config, forecast(slot)
target = arriveBy - restOfTripMin                       // must reach El Rosario by this
onTime(slot, c) = slot + c.p90_total <= target          // still on time on a bad day
arrival(slot, c) = round5(slot + c.p50_wait + c.p50_ride + restOfTripMin)

usual = forecast(usualDepart)
if usual.n < 10 -> state "sin_dato"
  ("Todavía no hay suficientes viajes a tu hora. Registra el tuyo y ayuda a que haya dato.")
else if usual.seat_rate >= seatGoal and onTime(usual) -> state "ya_sentado"
  ("A tu hora ya sueles ir sentado: X de cada 10.")
else search slots from usualDepart - 15 down to usualDepart - searchWindowMin:
  first slot with n >= 10, seat_rate >= seatGoal and onTime -> state "sugerencia"
  none -> state "sin_sugerencia"
  ("No encontramos una hora, hasta 1 h antes, en la que la mayoría de las veces se vaya sentado.")
if not onTime(usual): also show a warning
  ("Ojo: a tu hora, en un día malo, llegarías después de las HH:MM.")

output: { state, usual: {seatOutOf10, p50_wait, arrival, onTime, n},
          suggestion?: {slot, seatOutOf10, p50_wait, arrival, minutesEarlier, seatedMin: p50_ride, n},
          label: by min n of the slots shown: >=30 "Buen dato", 10–29 "Poco dato",
          hasSimulated }
```

Unit tests (with the seed numbers above, arrive 07:00, rest 75):
- usual 04:45 → `sugerencia` at **04:30**, 7 de cada 10, arrival ~6:30; usual 3 de cada 10, arrival ~6:50; minutesEarlier 15; seatedMin 33; label Poco dato · 12
- usual 04:15 → `ya_sentado` (8 de cada 10)
- arrive 06:00, usual 04:45 → `sin_sugerencia` + bad-day warning
- dayType domingo → `sin_dato`

The screen matches the mockup: green suggestion card, grey "A tu hora" card, the trade line "Cambias N min de sueño por ~M min sentado en la 120", "Metro + caminar: 75 min (estimado de Rodolfo)", and the label pill. The day picker shows weekday names: lunes–viernes → `laborable`.

## Ride logging

- `/registrar` requires Google sign-in (Supabase Auth, Google provider). Signed-out users are sent to sign-in and returned to `/registrar`.
- Fields: día; "¿A qué hora llegaste a la parada de la 120?" (15-min select, 03:00–11:45); "Minutos en la fila" (0–180); "Minutos arriba hasta El Rosario" (5–300); "¿Fuiste sentado?" (Sí / No, required, no default).
- zod schema in `src/lib/schemas.ts`, validated in a Server Action before the insert. DB constraints are the second line. Errors show inline in Spanish.
- Insert with `user_id = auth.uid()` and `is_simulated = false`. Success screen: "Tu viaje cuenta. Esta franja ahora tiene N viajes."
- `/mis-viajes`: the signed-in user's own rides with a **Borrar** button each (no edit). It also shows "Sentado: X de tus Y viajes" for his own rows. This is how Rodolfo's two-week test is read (PACKET §10).
- Sign-out link in the header when signed in.
